1. 这是一个什么项目

这是一个最小可运行的 AI 聊天网站 Demo。你在网页输入一条消息后，前端读取输入内容，浏览器把消息发送到 Flask 后端接口，后端调用 OpenAI 模型，模型返回回复，最后页面把回复展示出来。

这个项目的重点不在功能很多，而在流程完整：有页面、有后端接口、有模型调用、有异常兜底。

2. 技术栈说明

Python 负责后端逻辑，比如读取 Key、接收请求、调用模型、返回结果。

Flask 是轻量级 Python Web 框架，负责启动本地服务、提供网页地址 / 和聊天接口 /api/chat。

OpenAI Python SDK 用来从 Python 代码里调用 OpenAI 模型。

HTML 定义页面结构，CSS 控制视觉样式，JavaScript 负责点击发送、调用接口和渲染聊天记录。

Jinja2 是 Flask 默认模板引擎，负责把后端变量传入 HTML，例如当前是否是 OpenAI API 模式。

3. 文件职责

app.py 是后端主程序，负责创建 Flask 应用、读取 OpenAI Key、初始化客户端、提供页面和聊天接口。

templates/index.html 是前端页面，负责展示聊天 UI、管理输入框和按钮、调用后端接口、展示聊天记录。

README.md 是使用说明，TECHNICAL_DETAILS.md 是 Markdown 技术文档，当前这个 HTML 是为了稳定图像渲染准备的浏览器版本。

4. 浏览器和后端如何通信

页面通过 fetch() 向 /api/chat 发送 JSON：

{
  "message": "请解释什么是 few-shot prompting"
}

后端返回 JSON：

{
  "reply": "模型的回答内容"
}

5. 为什么需要后端

前端页面不能安全保存 OpenAI Key。把 Key 放在后端，前端只负责发消息，真正调用模型由后端完成，这样更安全，也更容易增加日志、鉴权、限流和错误处理。

6. 本地回退模式

如果程序没有读到 OpenAI Key，就会进入本地回退模式。这样即使暂时没有配置好 Key，也能先确认页面、接口和数据流转都正常。

7. Key 读取顺序

程序会按顺序查找 OPENAI_API_KEY 环境变量、C:\Openaikey、C:\Openaikey.txt，以及其他匹配 C:\Openaikey* 的文件。

8. 中级开发者怎么看这个架构

这是一个单体、最小、可学习的结构。它的优点是简单、清晰、方便扩展；当前还没有多轮上下文、日志分层、鉴权限流、提示词配置化和聊天记录持久化。

继续演进时，通常会把模型调用拆成 service，把配置集中管理，并加入多轮会话、错误日志、请求耗时统计和基础安全控制。
