# W1 核心概念对照表

## 适用范围

这份表是给 Week 1 学习收口用的，帮助快速区分几个最容易混淆的概念：

- Prompt Engineering
- Embedding
- Function Calling
- RAG
- Fine-tuning

---

## 一句话速记

- Prompt Engineering：优化“怎么问”
- Embedding：把文本变成“可比较的向量”
- Function Calling：让模型“会用工具”
- RAG：让模型“会查资料”
- Fine-tuning：让模型“长期改变行为”

---

## 核心对照表

| 概念 | 它解决什么问题 | 它本质上在做什么 | 是否需要外部数据 | 是否改变模型参数 | 最典型场景 |
| --- | --- | --- | --- | --- | --- |
| Prompt Engineering | 回答不稳定、格式不对、指令不清 | 通过提示词设计约束模型输出 | 不一定 | 否 | 让模型按指定格式输出、提高回答质量 |
| Embedding | 机器难以直接理解文本语义关系 | 把文本映射成向量，便于计算相似度 | 可有可无 | 否 | 语义搜索、聚类、推荐、去重 |
| Function Calling | 模型不会真正操作外部系统 | 让模型输出结构化工具调用，再由程序执行 | 是 | 否 | 查天气、查数据库、发邮件、调 API |
| RAG | 模型知识不新、不含私有资料、容易编造 | 先检索相关资料，再把资料作为上下文交给模型回答 | 是 | 否 | 企业知识库问答、文档问答、课程资料问答 |
| Fine-tuning | 模型默认风格/能力不贴业务 | 用训练数据持续调整模型行为 | 是 | 是 | 固定语气、稳定任务风格、领域化输出 |

---

## 最容易混淆的区别

### 1. Prompt Engineering vs Fine-tuning

- Prompt Engineering 是“通过问法优化结果”
- Fine-tuning 是“通过训练改变模型”

判断方法：

- 如果你只是改提示词，没有训练模型，那就是 Prompt Engineering
- 如果你拿样本数据训练出了一个更贴合任务的新模型，那就是 Fine-tuning

### 2. Embedding vs RAG

- Embedding 是底层表示方法
- RAG 是一整套应用流程

判断方法：

- 如果你在讨论“文本如何变成向量”，那是 Embedding
- 如果你在讨论“怎么检索资料再回答问题”，那是 RAG

一句话理解：

- Embedding 是 RAG 常用的基础能力之一
- 但 Embedding 不等于 RAG

### 3. Function Calling vs RAG

- Function Calling 解决“去哪里拿能力”
- RAG 解决“去哪里拿知识”

判断方法：

- 如果模型需要调用函数、API、数据库动作，那偏 Function Calling
- 如果模型需要先检索文档片段再回答，那偏 RAG

### 4. RAG vs Fine-tuning

- RAG 更适合接入“最新知识、私有知识、经常变化的知识”
- Fine-tuning 更适合固化“输出风格、任务习惯、领域行为”

判断方法：

- 问题是“模型不知道我的资料” -> 先想 RAG
- 问题是“模型知道了，但说得总不符合我要求” -> 再考虑 Fine-tuning

---

## 从工程角度看它们的关系

一个真实 AI 应用里，这几个概念常常不是互斥的，而是会组合出现：

1. 用 Prompt Engineering 控制输出格式和角色
2. 用 Embedding 构建语义检索能力
3. 用 RAG 把检索到的知识送进上下文
4. 用 Function Calling 调外部工具或业务接口
5. 用 Fine-tuning 在后期优化长期稳定性

也就是说：

- Prompt Engineering 是最先上手的
- Embedding 是很多检索能力的基础
- RAG 是知识增强方案
- Function Calling 是动作增强方案
- Fine-tuning 是后期优化方案

## 最后用一句话把它们串起来

当我们想把 AI 应用做得更像真实产品时，通常会这样演进：

- 先学会怎么问：Prompt Engineering
- 再学会怎么找相似内容：Embedding
- 再学会怎么把资料接进回答：RAG
- 再学会怎么调用外部能力：Function Calling
- 最后在必要时训练成更稳定的专用模型：Fine-tuning
